# 캐릭터 프리팹 구조와 모델 연결 규격

작성자: 송예찬 · 2026-11-01

목표: 바르코3D로 제작한 모델을 정해진 슬롯에 넣고 연결하여 사용한다.
게임 로직이 참조하는 루트와 기준점은 유지하고, 모델만 교체한다.
현재는 구성 골격이며 이동·손님 AI·애니메이션 제어·전투가 구현된 프리팹은 아니다.

## 구현 전 의사코드 — 프리팹 골격 생성

1. Player·Guest·Enemy의 루트 오브젝트를 만든다. Player에는 CharacterController, Guest·Enemy에는 CapsuleCollider를 둔다.
2. VisualRoot/ModelSlot을 만들고 크기 확인용 임시 모델을 넣는다. 임시 모델에는 충돌체를 남기지 않는다.
3. 모델과 독립적인 Anchors 하위에 얼굴·접시·상호작용·카메라 기준점을 둔다.
4. PrefabUtility로 각각 별도 프리팹을 저장한다. 기존 프리팹은 덮어쓰지 않는다.
5. 루트·슬롯·기준점·충돌체가 존재하는지 검증한다. 씬에 임의로 배치하지 않는다.

## 공통 계층

```text
PF_Player / PF_Guest / PF_Enemy
├─ VisualRoot                  외형 위치·방향·크기를 보정하는 곳
│  └─ ModelSlot                바르코3D 모델을 넣는 곳
│     └─ Placeholder           모델 연결 시 제거하는 임시 외형
└─ Anchors                     로직이 사용하는 기준점
   ├─ InteractionOrigin        상호작용 기준
   ├─ FacePoint                응대 카메라·이름 표시 기준
   ├─ PlatePoint               접시·소품 연결 기준
   └─ CameraTarget             카메라 추적 기준
```

| 구역 | 맡는 것 | 담당 |
| --- | --- | --- |
| 루트 | 위치·이동·충돌·guestId 등 로직 연결. 모델 교체 때 유지 | 김언호 |
| VisualRoot·ModelSlot | 바르코3D 모델 임포트·배치·축/크기/재질 정리 | 이기혁 |
| Animator·Avatar·클립 | 모델의 리그/클립 제공과 Animator 연결. 제어 파라미터는 개발자와 계약 | 이기혁·김언호 |
| Anchors | 이름과 의미 고정, 모델에 맞춰 높이·오프셋 조정 | 이기혁 배치, 김언호 확인 |
| 응대 초상·상태 UI | 3D 모델과 별도로 guestId와 종족·직업·취약점 데이터로 표시 | 홍준우·이기혁 |

충돌체·이동 스크립트·상태 컴포넌트를 가져온 모델의 뼈나 메시 아래에 붙이지 않는다.
로직은 바뀔 수 있는 메시 이름·본 이름으로 모델을 검색하지 않는다. 루트/연결 필드와 고정 기준점을 사용한다.

## 모델을 넣을 때

1. 바르코3D 원본과 사용 리소스 정보를 보관하고 Unity용 모델·텍스처를 임포트한다.
2. ModelSlot 아래에 모델을 넣고 Placeholder를 제거한다. 씬 인스턴스가 아니라 해당 캐릭터용 프리팹/변형에 적용한다.
3. 발바닥은 루트 Y=0, 앞쪽은 +Z, 위쪽은 +Y를 기준으로 VisualRoot에서 크기·회전을 맞춘다.
4. 루트는 scale 1을 유지한다. 캐릭터별 높이·충돌체 크기는 모델에 맞춰 확인하며 임시 치수를 최종값으로 취급하지 않는다.
5. 리그가 있으면 모델의 Animator·Avatar·컨트롤러를 연결한다. 뿌리의 실제 이동은 로직이 맡으므로 Root Motion 사용은 개발자와 맞춘다.
6. FacePoint·PlatePoint·CameraTarget 위치와 불필요한 모델 내부 콜라이더·카메라·라이트를 확인한다.
7. 김언호가 이동·충돌·상호작용 연결을, 홍준우가 응대/표시 연결을 확인한다.

모델을 넣기만 해도 서로 다른 리그·재질·좌표계가 자동 보정된다는 뜻은 아니다.
연결 규격을 맞춘 뒤에는 게임 로직 구조를 바꾸지 않고 외형을 교체할 수 있도록 한다.

## 프리팹별 범위

- PF_Player: CharacterController와 카메라·상호작용 기준점. 실제 이동·입력은 후속 개발 작업.
- PF_Guest: 손님 외형·충돌과 응대·접시 기준점. 방문·좌석·조리·귀환 상태는 후속 개발 작업.
- PF_Enemy: 같은 규격을 확인할 확장용 골격. 현 식당 씬에 배치하지 않으며 추적·공격·피해·전투 구현을 추가하지 않는다.

기존 프리팹 담당 규칙을 유지한다. 이기혁은 외형을 만들고, 기능과 실제 씬 통합은 김언호가 연결한다.

## 완료 기준

모델 교체 후에도 루트 이름·참조·기준점 구조가 유지되고, 중복 충돌체가 없으며 크기·앞 방향·접지 위치를 확인한다.
프리팹 골격 생성 완료와 실제 캐릭터 기능 구현 완료는 구분한다.
