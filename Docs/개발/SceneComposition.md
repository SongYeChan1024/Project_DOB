# 씬 분리와 조합 로드 설계

작성자: 송예찬 · 2026-11-01

승인 범위: Title·Loading·Restaurant·Gameplay·Tutorial·ReturnReport·CharacterTest의 일곱 씬으로 나눈다.
일반 영업은 Restaurant + Gameplay, 첫 플레이 구성은 Restaurant + Gameplay + Tutorial을 함께 로드한다.
CharacterTest는 공용 캐릭터 프리팹을 검증하는 개발용 씬이며 플레이어 빌드에는 포함하지 않는다.
이번 작업은 씬·로드·프리팹 연결 골격이다. 실제 이동·손님 AI·조리·정산·저장·튜토리얼 단계 판정·사운드 시스템 구현은 포함하지 않는다.

## 구현 전 의사코드

### 화면 요청과 씬 조합

1. Title 요청은 Title 하나, Restaurant 요청은 Restaurant·Gameplay, Tutorial 요청은 Restaurant·Gameplay·Tutorial, ReturnReport 요청은 ReturnReport 하나로 변환한다.
2. 빈 이름·미지원 경로·빌드 등록 누락은 현재 씬을 바꾸기 전에 거절한다. Loading은 전환 내부에서만 사용하며 CharacterTest는 런타임 전환 대상으로 삼지 않는다.
3. 이미 전환 중이면 다음 요청을 무시한다. 모든 추가 씬이 준비되고 Loading이 정리될 때까지 잠금을 유지한다.
4. 전환 전용 호스트를 만들고 유지한 뒤 Loading을 Single로 연다. 기존 화면과 추가 씬은 이때 함께 정리된다.
5. Loading 화면을 유지하며 목표 조합을 Additive로 차례로 연다. 일반·튜토리얼 영업의 활성 씬은 Restaurant으로 지정한다.
6. 조합 로드 진행률을 Loading 화면에 전달한다. 각 씬은 자기 역할의 오브젝트만 가진다.
7. 조합이 준비되면 Loading을 언로드하고 호스트·잠금을 정리한다. 카메라·조명·EventSystem·캐릭터가 재진입 때 중복되지 않아야 한다.
8. 전환 호스트는 게임 세션·금화·재고·튜토리얼 완료 사실을 소유하지 않는다. 해당 저장·복구 계약은 후속 개발로 남긴다.

### 씬 작성과 책임

1. 기존 씬·메타와 사용자 변경을 보존할 백업을 먼저 만든다. 이번 승인 범위의 기존 세 씬만 역할에 맞게 재구성하고 GUID를 유지한다.
2. Title과 ReturnReport에는 해당 화면·카메라·입력 연결을 둔다. Title에는 일반 영업·튜토리얼 구성 확인 버튼을 둔다.
3. Loading에는 진행률 표시와 전환 화면만 둔다. 독립 게임 상태나 캐릭터·상호작용 입력을 두지 않는다.
4. Restaurant에는 바닥·기본 조명·건물/가구 배치 영역·입구/응대/좌석/주방/계단 기준점만 둔다. 게임 UI·캐릭터·실행 매니저는 Gameplay로 분리한다.
5. Gameplay에는 공용 PF_Player·PF_Guest를 사용하는 임시 캐릭터 배치와 카메라·입력·확인용 화면, 후속 시스템 연결 영역을 둔다. 실제 캐릭터 기능 완료로 표시하지 않는다.
6. Tutorial에는 첫 손님 세 명과 단계·안내 연결 영역을 둔다. 공통 식당·캐릭터·카메라·입력을 복제하지 않는다. 구성 확인 버튼은 실제 튜토리얼 완료 저장을 수행하지 않는다.
7. CharacterTest에는 바닥·카메라·조명과 PF_Player·PF_Guest·PF_Enemy의 연결 인스턴스를 둔다. 테스트 씬에서 생긴 외형 변경은 공용 프리팹을 통해 인계한다.
8. 에디터 메뉴로 일반·튜토리얼 조합과 CharacterTest를 열 수 있게 한다. 저장하지 않은 씬 변경이 있으면 Unity의 정상 저장 확인 절차를 따른다.

### 검증 순서

1. 일곱 씬 파일과 메타, 런타임 여섯 씬의 빌드 등록·순서, CharacterTest 빌드 제외를 검사한다.
2. Restaurant·Tutorial에 중복 카메라·EventSystem이 없고, 실행 조합에 필요한 캐릭터·카메라·입력·기준점이 있는지 검사한다.
3. 실제 버튼으로 Title → 일반 영업 → ReturnReport → 일반 영업 → Title과 Title → 튜토리얼 → 일반 영업 → Title을 왕복한다.
4. 같은 프레임 반복 요청, 추가 씬 로드 중 반복 요청, 이전 조합 잔류·중복 생성·Loading 잔류를 검사한다.
5. 개발용 씬의 공용 캐릭터 프리팹 연결과 런타임 여섯 씬으로 Windows 개발 빌드를 확인한다.

## 씬별 소유 범위

| 씬 | 소유하는 것 | 주 편집·연결 |
| --- | --- | --- |
| Title | 시작 화면과 일반/튜토리얼 진입 요청 | 홍준우, 로드 계약은 김언호 |
| Loading | 전환 배경·진행률 표시 | 홍준우, 로드는 김언호 |
| Restaurant | 공간·바닥·조명·배치 기준점 | 이기혁 |
| Gameplay | RuntimeCharacters·Systems·카메라·입력·확인용 화면 | 김언호, 화면 프리팹은 홍준우 |
| Tutorial | TutorialFlow·첫 손님 세 명의 연결 영역·안내 화면 | 김언호 통합, 송예찬 기준, 홍준우·이기혁 리소스 |
| ReturnReport | 귀환 보고 화면과 식당/타이틀 복귀 요청 | 홍준우, 정산·세션은 김언호 |
| CharacterTest | 공용 캐릭터 세 종류의 독립 검증 배치 | 김언호, 모델·애니메이션은 이기혁 |

현재 Gameplay의 플레이어·손님은 공용 프리팹을 연결해 놓은 임시 배치다. 실제 스폰·이동·손님 상태 구현으로 판정하지 않는다.
이후 생성 서비스는 생성한 캐릭터를 Gameplay 씬에 소속시키고, Restaurant 기준점은 조합 로드가 완료된 뒤 연결한다. 서로 다른 씬의 오브젝트를 저장된 직접 참조로 묶지 않는다.
Tutorial의 일반 영업 전환 버튼은 조합 로드 확인용이며 튜토리얼 완료 사실을 저장하지 않는다. 안내 3명의 실제 데이터·단계 잠금·다음 아침까지의 진행은 후속 작업이다.

## 구현·검증 상태

- 의사코드 선작성 후 로더·표시 Presenter·에디터 생성/검증·주석을 맞췄다.
- 일곱 씬 생성·역할·빌드 등록·프리팹 연결 검사 통과. 런타임 빌드는 여섯 씬이며 CharacterTest는 제외한다.
- PlayMode 검사 4개 통과: 실제 버튼의 영업/보고 왕복, 튜토리얼 조합·정리, 전체 전환 중 반복 요청 차단, 내부·개발용·미지원 경로 거절과 빌드 목록 검증.
- 실행 조합의 카메라·AudioListener·EventSystem 각 1개, Gameplay 소유 플레이어·손님 각 1개, 이전 조합·Loading·전환 호스트 잔류 없음 확인.
- 기존 세 씬 GUID 유지, Assets 메타 누락 없음·GUID 72개 고유성 확인. Unity 6000.4.0f1·URP 17.4.0·사용자가 저장한 재질 업그레이드 설정 유지.
- Unity의 실제 Project 창에서 일곱 씬 표시와 Restaurant·Gameplay·Tutorial 동시 열기를 확인했다.
- 런타임 여섯 씬의 Windows 개발 빌드 성공. 로컬 확인용 실행 파일은 `Build/SceneComposition/DOB.exe`에 두며 빌드 출력은 Git에서 제외한다.

씬 등록 누락은 전환 전에 거절한다. 디스크 오류 등 예기치 않은 실제 로드 실패 때 이전 화면을 자동 복원하는 기능은 포함하지 않는다.
