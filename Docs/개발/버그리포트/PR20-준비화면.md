## [준비 UI] 제출 프리팹을 배치해도 준비 화면 5종이 모두 열리지 않음

**등급** 막힘. 준비 화면의 공용 진입점으로 다섯 화면 중 하나도 열 수 없습니다.

**환경** Windows, Unity `6000.4.0f1` 에디터 PlayMode. PR #20 커밋 `8d037bb`와 당시 `main`(`e5c1393`)을 합친 후보 `afd38d8`에서 각각 재현했습니다.

**전제** 다른 준비 화면 Presenter가 없는 빈 테스트 씬에 제출본 `Assets/_DOB/03.Prefabs/UI/PF_PrepScreens.prefab`을 그대로 배치합니다. 이 검사에서는 컴포넌트나 참조를 추가하지 않습니다.

**재현 방법**

1. Play Mode에 진입한 뒤 인스턴스에서 비활성 자식까지 포함해 `PrepScreenPresenter` 개수와 `PrepScreensView`의 다섯 화면 참조를 확인합니다.
2. 테스트 코드에서 `UIManager.OpenPrepScreen(screen)`에 `PrepScreen.Market`, `RecipeBook`, `Notebook`, `Upgrade`, `DoorSign`을 차례로 전달합니다. 각 호출의 반환값과 보이는 화면을 확인합니다.

**기대 결과** 프리팹이 활성화되면 Presenter가 등록되고, 각 호출이 `true`를 반환하며 요청한 화면이 표시됩니다.

**실제 결과** Presenter는 0개, 연결된 화면 View는 5개, Missing Script는 0개였습니다. 다섯 호출 모두 `false`를 반환했고 화면은 열리지 않았습니다. 프리팹 루트에는 `PrepScreensView`가 있고, 등록 코드는 `PrepScreenPresenter.OnEnable()`에 있습니다. [제출 프리팹의 루트](https://github.com/SongYeChan1024/Project_DOB/blob/8d037bb58829eb10583c077a48159e43408d8abd/Assets/_DOB/03.Prefabs/UI/PF_PrepScreens.prefab#L2351-L2360) · [Presenter 등록](https://github.com/SongYeChan1024/Project_DOB/blob/8d037bb58829eb10583c077a48159e43408d8abd/Assets/_DOB/02.Scripts/Presenter/PrepScreenPresenter.cs#L55-L69) · [공용 진입점](https://github.com/SongYeChan1024/Project_DOB/blob/8d037bb58829eb10583c077a48159e43408d8abd/Assets/_DOB/02.Scripts/Manager/UIManager.cs#L113-L121)

**재검증 기준** 새 테스트 씬에 수정된 프리팹을 배치한 뒤, 테스트 코드에서 참조를 주입하지 않아도 다섯 호출이 각각 성공하고 한 번에 한 화면만 표시됩니다.

## [준비 UI] 문패의 ‘문 열기’를 연속 클릭하면 영업 시작 요청이 두 번 전달됨

**등급** 중요. 문패를 한 번 연 상태에서 영업 시작 구독자가 같은 요청을 두 번 받습니다.

**환경** Windows, Unity `6000.4.0f1` 에디터 PlayMode. PR #20 커밋 `8d037bb`와 통합 후보 `afd38d8`(`main e5c1393` 기준)에서 각각 재현했습니다.

**전제** 독립 테스트 씬의 프리팹 인스턴스를 비활성화하고, 테스트용 `PrepScreenPresenter`를 추가해 `view`에 같은 루트의 `PrepScreensView`를 연결한 뒤 활성화합니다. 포인터 입력용 `EventSystem`을 두고, `UIManager.StartBusinessRequested`에 호출 횟수를 세는 구독자 하나를 등록합니다.

**재현 방법**

1. `UIManager.OpenPrepScreen(PrepScreen.DoorSign)`으로 문패를 열고 페이드 인이 끝날 때까지 기다립니다.
2. ‘문 열기’ 버튼 중앙을 클릭하고 약 60ms 뒤 같은 위치를 다시 클릭합니다. 두 번째 클릭은 0.15초인 닫기 페이드 도중에 들어갑니다.
3. 자동 재현 시에는 두 클릭마다 `EventSystem.RaycastAll`로 해당 좌표의 수신 대상을 다시 찾고, 적중한 버튼에 포인터 클릭을 전달합니다. 첫 클릭 직후의 `UIManager.IsPrepScreenOpen`과 두 클릭 후의 이벤트 횟수를 기록합니다.

**기대 결과** 첫 클릭으로 문패가 닫히기 시작하며, 같은 문패에서 영업 시작 요청은 한 번만 전달됩니다.

**실제 결과** 첫 클릭 직후 `IsPrepScreenOpen`은 `false`였습니다. 두 번째 클릭도 `OpenButton`에 적중해 같은 구독자가 총 2회 호출됐습니다. 클릭 간격은 PR 커밋에서 60.25ms, 통합 후보에서 60.30ms였습니다. 측정한 값은 이벤트 수신 횟수이며, 실제 영업 일차가 두 번 바뀌는지는 후속 씬 연결에서 확인할 사항입니다. [문 열기 처리](https://github.com/SongYeChan1024/Project_DOB/blob/8d037bb58829eb10583c077a48159e43408d8abd/Assets/_DOB/02.Scripts/Presenter/PrepScreenPresenter.cs#L132-L137) · [닫기 페이드와 포인터 입력](https://github.com/SongYeChan1024/Project_DOB/blob/8d037bb58829eb10583c077a48159e43408d8abd/Assets/_DOB/02.Scripts/UI/PrepScreensView.cs#L94-L117)

**재검증 기준** 같은 위치를 60ms 간격으로 두 번 클릭해도 이벤트가 1회만 전달됩니다. 문패를 다시 열어 한 번 클릭하면 새 요청 1회가 추가됩니다.

## [준비 UI] 수첩이 열린 상태에서 Esc를 눌러도 닫히지 않음

**등급** 사소. 수첩 닫기 버튼은 제공되며, PR의 확인 항목에 명시된 Esc 단축키로 닫는 경로에서 재현됩니다.

**환경** Windows, Unity `6000.4.0f1` 에디터 PlayMode, Unity Input System. PR #20 커밋 `8d037bb`와 통합 후보 `afd38d8`(`main e5c1393` 기준)에서 각각 재현했습니다.

**전제** 독립 테스트 씬의 프리팹 인스턴스를 비활성화하고, 테스트용 `PrepScreenPresenter`를 추가해 `view`에 같은 루트의 `PrepScreensView`를 연결한 뒤 활성화합니다. Esc를 대신 처리할 별도 입력 스크립트는 추가하지 않습니다.

**재현 방법**

1. `UIManager.OpenPrepScreen(PrepScreen.Notebook)`으로 수첩을 열고 페이드 인이 끝난 뒤 `UIManager.IsPrepScreenOpen`이 `true`인지 확인합니다.
2. Game 뷰에서 Esc를 한 번 눌렀다 뗍니다. PlayMode 자동 검사에서는 가상 키보드에 `KeyboardState(Key.Escape)`를 보내고 입력을 갱신한 뒤 `escapeKey.isPressed`가 `true`인지 확인합니다.
3. 두 프레임을 진행하고 키를 뗀 뒤, 수첩의 표시 상태와 `UIManager.IsPrepScreenOpen`을 확인합니다.

**기대 결과** Esc 한 번으로 열린 수첩이 닫힙니다. [PR의 Esc 확인 항목](https://github.com/SongYeChan1024/Project_DOB/pull/20)

**실제 결과** 두 커밋 모두 Esc 눌림이 Input System에 전달됐지만 수첩은 열린 채였고 `IsPrepScreenOpen`도 `true`였습니다. 수첩 닫기 버튼의 이벤트와 공용 닫기 메서드는 각각 구현돼 있습니다. [수첩 닫기 버튼](https://github.com/SongYeChan1024/Project_DOB/blob/8d037bb58829eb10583c077a48159e43408d8abd/Assets/_DOB/02.Scripts/UI/PrepNotebookView.cs#L96-L109) · [공용 닫기 메서드](https://github.com/SongYeChan1024/Project_DOB/blob/8d037bb58829eb10583c077a48159e43408d8abd/Assets/_DOB/02.Scripts/Manager/UIManager.cs#L124-L128)

**재검증 기준** Esc 한 번에 `IsPrepScreenOpen`이 `false`가 되고, 닫기 페이드가 끝나면 수첩이 사라집니다. 수첩을 다시 열어 같은 동작을 반복할 수 있습니다.
