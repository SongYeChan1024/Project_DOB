# 다녀왔어: 층계참 식당 — 메인 기획서

작성자: 송예찬 · 원본: [팀 노션 기획](https://app.notion.com/p/3fff7d6373c381a49d71e04d2750ef15) · [구글 메인기획서](https://docs.google.com/document/d/1nFDNT7zw3tflOq4N4xJNqzioT0eQcbbVXVVCzUswXOE)

손님의 말과 차림에서 던전의 위험을 읽고, 요리와 자리로 돌아올 준비를 돕는 정보 추리 식당 경영 게임이다. 한 끼의 맛은 떠날 때, 그 처방이 탐험에 얼마나 도움이 됐는지는 다음 아침에 알게 된다.

게임 기획은 노션 「기획」이 우선이다. Git에서는 영업·호감·입소문·데모 기준을 [FeatureManagerMap](../개발/FeatureManagerMap.md)에서, 결정 상태를 [현재 결정과 검토 사항](08-결정필요사항/현재결정과검토사항.md)에서 확인한다. 사용자 승인은 팀 전원 합의나 구현 완료와 구분한다.

## 하루는 이렇게 흘러간다

| 언제 | 하는 일 | 자세히 |
| --- | --- | --- |
| 영업 전 | 새 게임은 0일차 연습으로 시작한다. 1일차는 전날 보고 없이 준비(시장)부터 한다 | [하루 영업 순서](04-핵심플레이/02-하루영업순서.md) |
| 문을 연 동안 | 손님 응대·추리 → 자리 안내 → 요리 → 서빙 → 식후 반응 → 방명록을 쓰고 퇴장 | [손님 응대와 처방](04-핵심플레이/01-손님응대와처방.md) |
| 문을 닫은 뒤 · 다음 날 | 모든 방문이 끝나면 마감·당일 정산 → 자동 저장 → 다음 날 아침 귀환 보고 → 준비 | [귀환 보고와 재방문](04-핵심플레이/07-귀환보고와재방문.md) |

| 기준 | 내용 |
| --- | --- |
| 만드는 순서 | 1일차 본영업 루프 → 데모 엔딩 → 0일차 튜토리얼 → 남은 시간에 스토리 |
| 데모 엔딩 | 본영업 하루에 서로 다른 손님 12명 이상에게 실제 서빙을 마친 날, 마감·정산창을 확인한 뒤 → [성장과 데모 엔딩](04-핵심플레이/09-성장과데모엔딩.md#데모-엔딩) |
| 호감·입소문 수치 | 💡 시험값, 팀 합의 전 → [호감과 입소문](04-핵심플레이/08-호감과입소문.md) |
| 하루 손님 수 (2026-11-25) | 1일차 3명. 이후 재방문 손님 + 입소문 신규 0~4명이며 결원은 채우지 않는다. 예: 매일 +3명이면 3 → 6 → 9 → 12명 → [실제로 오는 손님](04-핵심플레이/08-호감과입소문.md#실제로-오는-손님) |
| 저장 (2026-11-25) | 자동은 일차를 넘기는 시점, 수동은 누른 시점 → [저장 기준](09-승인과제작기준/02-제작순서와저장기준.md#저장-기준) |
| 던전 돌발 | 스토리 이후 안건. 기본 위험·부상은 유지 → [던전 위험 판정](04-핵심플레이/03-던전위험판정.md) |
