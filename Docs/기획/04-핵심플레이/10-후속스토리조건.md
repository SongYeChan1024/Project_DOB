# 4-10. 후속 스토리 조건

[← 4장 목차](README.md) · [메인 기획서](../메인기획서.md)

> 스토리(양피지 독백·단골 사연·5층 구조)는 데모 완성 후 남은 시간에 구현한다([FeatureManagerMap F12](../../개발/FeatureManagerMap.md#저장과-후속-제작--튜토리얼-사운드-스토리)). 첫 본영업 루프는 서사 재생 없이도 귀환 정산·준비·재영업을 마칠 수 있어야 한다. 아래 트리거·처리 규칙은 제안이며, 🔴·🟡 항목은 확정하지 않았다.

이 문서는 스토리가 **핵심 루프와 만나는 지점**만 정리한다. 트리거 ID별 조건, A안 단서 순서, 저장 데이터, 예외·확인 기준의 전체 표는 [동료 구조 사건과 조건](../03-세계관과스토리/동료구조사건과조건.md)에 있다.

## 이야기의 목표 (스토리 엔딩)

옛 파티의 현재 생존을 확인하고, 5층 고립 구역의 위치·우회 접근로·장비 계획을 마련한 뒤, 자기 처방과 동료의 귀환에 보탤 도시락을 준비한다. 준비가 유효한 상태에서 대상 계단 상호작용을 확인하면 주인공이 직접 내려가는 장면으로 이어진다. 층 개방과 이야기는 따로 관리하며, **5층 대성공 자체는 엔딩 조건이 아니다.**

| 엔딩 뒤 | 규칙 |
| --- | --- |
| 연출 | 계단 출발 뒤 짧은 구조·귀환 후일담을 컷씬(시네머신)이나 일러스트로 보여 준다. 직접 조작하는 구조 던전·전투·동료 직원·신규 모델은 필수가 아니다 |
| 복귀 | 함께 돌아온 뒤 식당으로 복귀해 준비 → 영업 → 마감 → 귀환 보고를 이어 간다. 금화·재료·설비·단골·열린 층을 유지한다 |
| 상태 | 귀환 후 `storyPhase = AfterReturn`으로 바꾸고 옛 파티 조사 임무의 새 배정을 끝낸다 |
| 저장 | 안전한 아침 경계에서 출발하고 출발·귀환·확인 완료 단계를 저장해 비용·보상 중복을 막는다. 생략·다시 보기는 상태·보상을 바꾸지 않는다 |
| 부재 기간 | 날짜·매출·부상 회복을 임의로 계산하지 않는다 |
| 🟡 가안 | 자기 처방·왕복 위험·장비·도시락의 세부 검증 기준 |

게임 오버는 없다. 기본 재료는 무료·무제한이고, 자원이 바닥났다는 이유만으로 저장 파일의 진행이나 필수 이야기가 막히지 않는다. 대성공만 이어지거나 희귀 재료가 나오지 않아도 필수 단서를 다시 배정받아 엔딩에 닿을 수 있어야 한다.

이 스토리 엔딩은 [4-9의 데모 엔딩](09-성장과데모엔딩.md#데모-엔딩)(하루 12명 서빙)과 별개다.

## 플레이어 규칙

손님을 보내고 다시 맞으며 돌아올 여력을 남기는 법을 배우고, 그들이 가져온 단서를 모아 5층에서 일어난 일을 알아낸다. 준비가 되면 자신에게도 한 끼를 내어 줄 수 있다. 실패한 결과가 이야기를 영구히 막지 않는다. 결과와 발견한 사실은 기록에 남고, 필요한 단서는 다시 확인할 기회가 있다.

## 핵심 루프와 만나는 곳

| 원칙 | 내용 |
| --- | --- |
| 결과만 읽는다 | 위험 판정과 손님 보상은 기존 규칙이 담당한다. 스토리는 확정된 귀환 보고와 단서를 읽을 뿐, 대사를 고르려고 위험·보상·호감 계산을 다시 돌리지 않는다 |
| 확정 뒤에만 | 귀환 결과·보상·손님 상태가 저장된 뒤 이벤트를 발행한다. 저장이 실패하면 발행하지 않는다 |
| 안전한 재생 시점 | 그 아침의 귀환 보고와 필수 정산을 모두 끝낸 뒤 장면을 고른다. 한 아침에 서사 장면은 하나(설정값)이고 나머지는 대기한다. 손님별 일반 귀환 결과는 항상 처리한다 |
| 우선순위 | 주요 사건·단서 → 첫 결과 → 관계·회복. 같은 순위는 조건 충족 순번 → 트리거 ID 순 |
| 중복 없음 | 이벤트·보고·단서 ID로 중복을 막는다. 보고 저장 후 스토리 저장 전에 꺼졌다면 다음 시작 때 누락 이벤트를 복구하되 보상은 다시 주지 않는다 |
| 첫 결과는 강요하지 않음 | 첫 대성공·성공·간신히·부상은 실제로 나왔을 때 각각 기록한다. 특정 결과를 만들라고 요구하거나 넷을 모두 봐야 이야기가 열리게 하지 않는다 |
| 영구 잠금 없음 | 필수 단서는 조건이 맞는 손님·보고에 다시 배정할 수 있다. 한 번의 부상·돌려보내기·추첨 실패로 영원히 못 얻게 하지 않는다. 숨은 사망 타이머도 없다 |
| 층과 이야기 분리 | 더 깊은 층이 먼저 열려도 이야기 단계를 자동으로 올리지 않는다 |
| 활력 보험 장면 | 「남겨 둔 힘 덕에 돌아왔다」 장면은 판정기가 실제로 돌발을 활력 여유로 흡수했다고 확정했을 때만 나온다. 활력 수치가 높다는 이유만으로 추정하지 않는다 |
| 자기 처방 | 기존 위험·효과 판정기를 그대로 쓴다. 정해진 요리 하나를 맞히는 열쇠 퀘스트로 만들지 않는다. 승인되기 전에는 자기 처방·엔딩 트리거를 꺼 두고 일반 영업은 계속한다 |

## 화면과 인물

- 별도 트라우마 게이지나 항상 떠 있는 감정 UI는 넣지 않는다. 식당 공간 안의 짧은 멈춤·도시락을 챙기는 동작·계단을 내려가는 연출을 검토한다.
- 귀환의 실패·간신히·성공·대성공에 짧은 독백을 붙이고, 주요 편린은 낡은 양피지 질감의 일러스트·문장으로 한 번씩 해금한다. 보고별 반응과 핵심 사실 해금을 분리한다.
- 말의 내용이 필수 단서라면 대사·기록 확인 수단을 첫 루프에 넣는다. 색·표정만으로 필수 사실을 전하지 않는다.
- 주인공은 A안 카엘이고, 메인 노션 Character Image Reference의 A안 남성 시트를 디자인 기준으로 쓴다. 옛 파티는 카엘·모라·시에 세 명이다.
- 손님 관찰과 귀환 보고 화면은 [6장 인터페이스](../06-인터페이스/README.md)를 따른다. 3D 제작 참고도의 번호는 개발 설명용이며 게임 UI가 아니다. 참고도의 인물은 임시 형태이고 주인공 외형 확정 자료가 아니다.

## 아직 정하지 않은 것

- 🔴 주인공(인간)의 직업·컨디션, 진입 경로의 위험, 도시락과 현장 식사의 차이, 귀환 여력 검증 기준. 일반 손님의 자리 효과를 출발 후에도 적용할지. 기존 판정이 귀환 여력을 표현하지 못하는 부분은 데이터와 단계별 판정 필요성을 먼저 검토하며, 명세 없이 새 공식을 추가하지 않는다.
- 🔴 필요한 장비·외부 협조·준비 완료 기준과 이를 기록할 요청 데이터. 엔딩 범위를 정한 뒤 작성한다.
