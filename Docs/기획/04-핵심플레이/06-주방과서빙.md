# 4-6. 주방과 서빙

[← 4장 목차](README.md) · [메인 기획서](../메인기획서.md)

## 조리 방법

주방 화면 가운데에 현재 조리도구를 두고, 좌우에 요리도구를 배치한다. 플레이어는 레시피에 맞는 재료와 양념을 직접 넣고 빼며 효과를 비교한다. 굽기·뒤집기·타이밍 미니게임은 요구하지 않는다.

1. 좌우에서 쓸 도구를 고른다.
2. 가운데에서 재료와 양념을 넣거나 뺀다. 효과·맛·차감 예정 재료가 바로 갱신된다.
3. 확정하면 한정 재고(양념·던전 재료)를 한 번 소비하고 **6초 자동 조리**를 시작한다. 💡 시작 화구는 2개다.
4. 조리하는 동안 이동·응대 등 다른 일을 할 수 있다. 대화·수첩·재료 선택 중에도 조리는 계속되고, Esc 일시 정지 메뉴에서만 멈춘다(FeatureManagerMap F2).
5. 완성된 접시를 들고 그 접시를 주문한 손님에게 가져간다.

| 규칙 | 내용 |
| --- | --- |
| 수량 | 고기 구이의 「고기 두 개 투입」은 예시다. 모든 레시피 수량을 두 개로 바꾸는 규칙이 아니다 |
| 취소 | 확정 전 취소는 실제 재고를 차감하지 않는다. 시작 후 취소 불가·완성 후 폐기는 초기 가안이다 |
| 중복 방지 | 같은 주문의 중복 확정·픽업·서빙을 막는다. 다른 손님에게 접시를 주려 하면 거절하고 접시를 유지한다 |
| 양념 칸 | 요리 하나에 한 칸. 양념 선반 개량 후 두 칸. 칸이 찼으면 다음 양념을 거절하고 재고는 그대로 |
| 조리도구 | 레시피에 따라 냄비·프라이팬·오븐을 나누는 안을 검토한다. 🔴 도구별 레시피 연결, 화구·동시 조리와의 관계, 해금 방식은 팀이 정한다. 댓글의 재료 조합은 조작 예시이며 레시피 수량을 바꾸는 확정안이 아니다 |

## 재료와 레시피

- 기본 재료(밀가루·감자·고기)는 **무료·무한**이다. 금화·양념이 없어도 기본 요리로 영업을 이어 간다.
- 시장 화면에서 사는 것은 양념 6종이다(시험 구현).
- 희귀 재료는 누적 개인 호감 9 이상인 손님이 다녀온 층에서 가져오는 선물이며, 시장에서 팔지 않는다(2026-11-25 사용자 정정).
- 일반 던전 재료를 행상인이 네 배 가격으로 파는 안은 데모 도입 여부와 가격이 정해지지 않았다.
- 재료를 처음 손에 넣으면 그 재료로 만들 수 있는 레시피가 열린다. 레시피는 모두 22개다. 🟡 재료 하나만 얻어도 여는지, 모두 얻어야 여는지는 [첫 영업 재료와 경제](../05-데이터/첫영업재료와경제.md#발견한-문제)에서 정한다. 특수 손님의 직접 레시피 보상과 기존 해금의 관계는 따로 검토한다.
- 양념은 효과 +1과 함께 맛 표현 하나를 더한다(예: 소금 = 활력 +1, 짭짤).

수치 표: [양념과 레시피](../05-데이터/양념과레시피.md) · [판정과 경제 상수](../05-데이터/판정과경제상수.md)

## 맛과 금화

| 항목 | 규칙 |
| --- | --- |
| 맛 표현 | 레시피와 양념마다 있다 — 고소, 담백, 진한, 시원, 달콤, 얼큰, 쌉쌀, 쿰쿰, 짭짤, 향긋, 바삭, 상큼, 알싸 |
| 맛 점수 (0~4) | 2에서 시작한다. 좋아하는 맛 하나당 +1(최대 +2), 싫어하는 맛이 들어가면 −2. 좋아하는 맛도 싫어하는 맛도 없으면 2를 유지한다 |
| 받는 금화 | 레시피 기본가 × (0.6 + 0.2 × 맛 점수) + 넣은 양념 수 |
| 전리품 보너스 | 맛 점수 3 이상이면 35% 확률로 전리품 +1개. 호감 36의 전리품 +1과 별개이며, 전리품·선물 자격(누적 호감 9 이상, [4-8](08-호감과입소문.md#누적-호감이-열어-주는-것))을 대신하지 않는다 |
| 위험 판정 | 맛은 위험 판정과 관계없다 |

**맛 점수와 방문 호감의 입맛은 다른 값이다.** 맛 점수 0~4는 금화와 전리품 보너스에 쓴다. 방문 호감의 입맛은 손님의 입맛 태그 두 개를 각각 맞으면 +1, 틀리면 −1로 매긴 −2·0·+2다([4-8](08-호감과입소문.md)).

예: 구운 빵(기본가 8)에 마늘을 넣고 맛 점수 2이면 8 × 1.0 + 1 = **9금**.

## 손님 취향

- 💡 취향은 손님마다 따로 쓰지 않고 생성 때 무작위로 정한다. 종족 대표 입맛은 유지하고 무작위 칸만 뽑는다([직업과 종족](../05-데이터/직업과종족.md#종족)). 맛 후보·좋아함/싫어함 개수·겹침 금지 같은 범위는 `08.Data`의 ScriptableObject에 둔다. 뽑은 취향은 그 손님의 guestId에 한 번 고정해 재방문·단골 전환·불러오기 때 다시 뽑지 않는다. 방명록·재방문 대사·호감 변화가 같은 취향을 기준으로 하기 때문이다. 난수는 저장·재현할 수 있도록 판정 System의 시드 난수를 쓰거나 뽑은 결과를 바로 저장하며, 전역 `UnityEngine.Random` 상태에 의존하지 않는다. 고정 시험 손님은 [취향 덮어쓰기](../05-데이터/시험손님과판정데이터.md#4-고정-입력-데이터-재현-시험용)를 쓴다.
- 단골의 취향은 처음에는 좋아하는 맛 하나만 알려져 있다. 맛있게 먹거나 싫은 맛을 먹은 반응으로 하나씩 드러난다.

## 서빙과 식후 반응

| 순서 | 일어나는 일 |
| --- | --- |
| 서빙 | 지정 손님에게 접시를 낸다. 같은 주문을 두 번 완료하지 않는다 |
| 맛 반응 | 맛 점수에 맞는 소감 한마디 |
| 각오 한마디 | 실제 부족 합에 맞는 출발 각오. 첫 완성본은 무작위 오차를 뺀다 |
| 금화 | 위 공식대로 지급 |
| 방명록 | 계단 옆 방명록에 식사 소감을 남긴다. 던전에 들어가기 전이므로 탐험 결과는 쓰지 않는다. 손님 이름별로 방문 순서대로 보이고, 내부 기록은 guestId로 구분한다 |
| 퇴장 | 💡 나가는 동안 머리 위 말풍선에 같은 맛 반응의 이모티콘(웃음·무표정·찡그림)을 띄우고 던전으로 내려간다 |

## 기획과 구현

- **기획**: 위 조리·서빙 규칙.
- **구현 (FeatureManagerMap의 14fd7e9 시점 대조, 이후 커밋은 다시 확인 필요)**: 구운 빵 한 주문의 확정 → 6초 조리 → 픽업 → 서빙이 연결되어 있었다. 마늘은 재고에 따라 쓰고, 마늘 사용 여부로 맛 소감 두 문장 중 하나를 고른다. 시험 빵은 8금, 마늘 빵은 9금이다. 좌우 도구 조작·재료 회수·두 화구 병행, 시장·가게 개량과 실제 지갑의 연결은 후속 작업이다([FeatureManagerMap F6·F8](../../개발/FeatureManagerMap.md#기능별-기획과-구현)).

주방 화면의 제작 참고(그림 6)는 [주방과 서빙 화면](../06-인터페이스/03-주방과서빙화면.md)에 있다.
