# 다녀왔어: 층계참 식당 — 메인 기획서

작성자: 송예찬 · 원본: [팀 노션 기획](https://app.notion.com/p/3fff7d6373c381a49d71e04d2750ef15) · [구글 메인기획서](https://docs.google.com/document/d/1nFDNT7zw3tflOq4N4xJNqzioT0eQcbbVXVVCzUswXOE)

손님의 말과 차림에서 던전의 위험을 읽고, 요리와 자리로 돌아올 준비를 돕는 정보 추리 식당 경영 게임이다. 한 끼의 맛은 떠날 때, 그 처방이 탐험에 얼마나 도움이 됐는지는 다음 아침에 알게 된다.

**읽는 순서** — 노션 「기획」이 우선이다. Git에서는 현행 영업·호감·입소문·데모 기준을 [구현 기능과 총괄 Manager 구성안 F10](../개발/FeatureManagerMap.md#손님-한-명의-방문-호감-계산)에서, 결정 상태를 [최신 결정과 적용 기준](08-결정필요사항/CurrentDecisions.md)에서 확인한다. 아래 장 본문은 기획 원안이며 💡 시험값·🟡·🔴 표시와 승인 이력을 그대로 보존한다. 사용자 승인은 팀 전원 합의나 구현 완료와 구분한다.

## 첫 본영업의 플레이 순서

타이틀 → 새로 시작 → 0일차 연습 → **1일차는 전날 귀환 보고 없이** 영업 준비(시장) → 영업 시작 → 응대·추리 → 자리 → 요리 → 서빙 → 식후 반응 → 방명록 작성·퇴장 → 영업 종료·당일 정산 → 자동 저장 → 다음 일차 시작 → 아침 귀환 보고 → 준비

- 제작 순서: 1일차 본영업 루프 → 데모 엔딩 → 0일차 튜토리얼 → 남은 시간에 스토리([FeatureManagerMap 제작 우선순위](../개발/FeatureManagerMap.md))
- 데모 엔딩: 본영업 하루에 서로 다른 손님 12명 이상에게 실제 서빙을 완료한 날, 마감·정산창 확인 후 엔딩([데모 확정 사양](../개발/FeatureManagerMap.md#데모-확정-사양--하루-12명-이상-서빙--마감정산--엔딩))
- 호감·입소문 수치: 💡 시험값([F10](../개발/FeatureManagerMap.md#손님-한-명의-방문-호감-계산))
- 손님 한 명의 루프: [4-1](04-핵심플레이/README.md#4-1-손님-한-명의-처방-루프) · 하루 흐름: [4-2](04-핵심플레이/README.md#4-2-하루-흐름)
- **현행 호감·입소문**(단골 9 · 입맛 −2/0/+2 · 결과 +2/+1/−1/−2 · 돌려보냄·이탈 각 −4 · 입소문 60/75/85/100%): [4-8 현행 기준](04-핵심플레이/README.md#현행-호감입소문-기준-2026-11-24)
- 남은 결정: [08 결정 필요 사항](08-결정필요사항/README.md) · [데모 본영업에 남은 결정](../개발/FeatureManagerMap.md#데모-본영업에-남은-결정)
