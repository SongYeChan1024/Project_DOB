# 손님 이름 목록 명세

작성자: 송예찬 · 작성일: 2026.10.26 · 수정: 2026.10.29

## 0 기획 의도

손님은 '솔', '하루'처럼 기억할 수 있는 이름으로 찾아온다. '떠돌이 검사', '지친 순례자'처럼 상태와 직업을 붙인 호칭은 쓰지 않는다. 이름과, 관찰로 알아내는 종족·직업·컨디션을 분리한다. 단골도 따로 정해진 인물이 아니라 과객이 단골이 된 것이므로, 과객일 때 받은 이름을 그대로 쓴다.

## 1 플레이어 규칙

손님은 자기 이름을 가지고 찾아오고, 다시 만나도 같은 이름이다. 단골이 되면 이름 옆에 [단골] 태그가 붙는다.

## 2 시스템 규칙

### 생성 순서

1. 새 손님을 만들 때 고유한 `guestId`를 부여한다. 방문마다 만드는 `visitId`와 구분한다.
2. 이름 목록에서 아래 중복 규칙에 걸리는 이름을 뺀다. 이름 선택은 종족·직업·레벨·컨디션·위험 판정과 독립적이다.
3. 남은 후보 중 하나를 같은 확률로 고른다. 가중치는 필요해질 때 검토한다.
4. 고른 `nameEntryId`와 `displayName`을 손님 데이터에 저장한다. 대화하거나 화면을 열 때마다 다시 뽑지 않는다.
5. 재방문, 저장 불러오기, 단골 전환 뒤에도 같은 `guestId`와 이름을 유지한다.

### 대상·중복·예외

| 상황 | 처리 |
| --- | --- |
| 단골이 된 과객 | 이름을 바꾸지 않는다. 이름 옆에 [단골] 태그를 붙인다. 태그는 `isRegular`가 true일 때만 보인다 |
| 같은 시간 식당에 있는 손님 | 지금 입장·대기 중인 손님의 이름을 후보에서 뺀다 |
| 현재 단골 | 지금 단골인 손님의 이름도 후보에서 뺀다. 같은 이름의 단골이 둘이 되어 헷갈리는 일을 막는다 |
| 다른 날의 서로 다른 과객 | 같은 이름을 다시 써도 된다. 이름이 같아도 `guestId`가 다르면 다른 사람이다 |
| 후보를 모두 씀 | 제외 규칙을 풀고 전체 목록에서 고른다(중복 허용). 손님 입장이 막히지 않게 한다 |
| 목록이 비어 있음 | 개발 중에는 오류를 표시한다. 실행 중에는 임시 표시 '손님'을 쓰고 판정은 막지 않는다 |
| 저장 데이터에 이름이 없음 | 손님마다 한 번 만들고 바로 저장한다 |
| 목록 항목이 바뀌거나 삭제됨 | 이미 만든 손님의 `displayName`은 유지한다. 새 손님부터 적용한다 |

### 추리 단서와 분리

- 이름에 '지친', '독에 약한', '5층에서 온' 같은 상태·정답 정보를 붙이지 않는다.
- `displayName`을 위험 공식, 종족 약점, 직업 보정, 사연·스토리 트리거의 식별자로 쓰지 않는다. 연결에는 `guestId`를 쓴다.
- 컨디션이 바뀌면 표정·자세·대사나 상태 태그만 바뀐다.

## 4 UI·피드백

- 대화창, 귀환 보고, 수첩이 같은 손님 데이터의 이름을 읽는다.
- 단골이면 이름 옆에 [단골] 태그를 붙인다(예: 하루 [단골]). 🔴 태그 모양·위치는 UI 작업 때 정한다.
- 머리 위 이름표를 항상 띄울지는 정하지 않았다.

### 구현 확인 기준

| 확인 상황 | 기대 결과 |
| --- | --- |
| 새 손님 생성 | 목록의 이름이 붙고 저장됨 |
| 대화 반복·저장 후 불러오기·재방문 | 이름이 그대로임 |
| 컨디션 변화 | 이름은 그대로, 상태 표현만 바뀜 |
| 과객이 단골이 됨 | 같은 `guestId`와 이름, [단골] 태그만 추가됨 |
| 같은 시간에 같은 이름 | 생기지 않음(후보가 남아 있는 동안) |
| 후보를 모두 씀 | 손님이 정상 입장하고 중복을 허용함 |
| 빈 목록 | 오류를 기록하고 '손님'으로 계속 진행함 |
| 같은 이름의 다른 손님 | 호감·귀환 결과·사연이 `guestId`별로 따로 저장됨 |
