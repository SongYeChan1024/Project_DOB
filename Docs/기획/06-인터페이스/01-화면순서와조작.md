## 하루의 화면 순서 (💡 2026-11-24 기준, 팀 합의 전)

| 순서 | 화면 | 들어가는 조건 | 다음으로 넘어가는 조건 |
| --- | --- | --- | --- |
| 1 | 타이틀 | 게임 실행 | 새로 시작 또는 이어하기 |
| 2 | 준비 (시장·레시피·수첩·가게) | 1일차는 바로, 2일차부터는 아침 귀환 보고 뒤 | 영업 시작 |
| 3 | 영업 — 맞이·응대 | 손님이 무작위 간격으로 입장 | E로 맞이하고 단서를 확인 |
| 4 | 영업 — 자리 안내 | 응대를 마친 손님이 따라옴 | 빈자리에 착석하면 주문이 열림 |
| 5 | 영업 — 주방 | 주문이 열림 | 조리 확정 → 6초 자동 조리 → 완성 접시 |
| 6 | 영업 — 서빙 | 완성 접시를 집음 | 그 주문의 손님에게 전달 |
| 7 | 식후 반응 → 방명록 → 퇴장 | 서빙 완료 | 방명록을 다 쓰고 던전 계단으로 내려감 |
| 8 | 마감 → 당일 정산 | 그날의 모든 방문이 끝남(방명록 완료·돌려보냄·대기 이탈) | 정산 확인 → 자동저장 |
| 9 | 다음 날 아침 귀환 보고 | 2일차부터. 전날 실제로 던전에 간(파견한) 방문 전부를 보고하고, 돌려보냄·대기 이탈처럼 파견하지 않은 방문은 보고하지 않는다. | 모든 보고 확인 → 준비로 |

- 1일차에는 전날 손님이 없으므로 귀환 보고 없이 준비에서 시작한다.
- 그날 받을 손님 수는 영업을 열 때 정한다(성장 단계 기본 인원 + 전날 입소문 추가 − 결석, [호감과 입소문](../04-핵심플레이/08-호감과입소문.md)). 손님은 그 뒤 무작위 간격으로 들어오며, 🔴 간격의 최소·최대·입구 줄 인원·입장 순서는 미정이다.
- 영업 시간 제한은 없다. 그날 받을 손님의 모든 방문이 끝나야 마감한다.
- 데모: 본영업 하루에 서로 다른 손님 12명 이상에게 실제 서빙을 마친 날은 8번의 정산 확인 뒤 데모 엔딩으로 넘어간다. 11명 이하이면 9번으로 이어진다([성장과 데모 엔딩](../04-핵심플레이/09-성장과데모엔딩.md)).
- 게임 오버 화면 분기는 없다.
- 게임 안에서는 0일차 연습 영업이 1일차보다 먼저 오지만, 제작은 본영업 루프 완성 후에 붙인다([첫 영업 장면 연출](첫영업장면연출.md)).
- 양피지 독백·회상 같은 스토리 장면은 본영업 루프의 필수 화면이 아니다. 첫 루프 사운드 신호와 데모를 완성한 뒤 남은 시간에 붙이며, 붙일 때는 귀환 보고 정산이 끝난 안전한 시점에 둔다([후속 스토리 조건](../04-핵심플레이/10-후속스토리조건.md)).

> **이전 문장 정리** — 예전 화면 순서 “제목 → 아침 귀환 보고 → 준비 → 영업 → 마감”과 “귀환 보고 뒤 독백·양피지 → 생존·위치·구조 준비 → 계단 출발”은 스토리를 포함한 10월 기준이다. 1일차에 보고가 없다는 점과 스토리가 후속이라는 점을 반영해 위 표로 바꿨다.

### 현재 구현 기록 (FeatureManagerMap, main `14fd7e9` 기준)

타이틀 → 새로 시작 → 로딩 → 1일차 영업에서 무작위 손님 1명 맞이 → 대사·초상 관찰 → 빈자리 안내 → 빵 조리·서빙 → 퇴장·방명록 → 마감 확인 → 2일차 임시 보고 → 준비·영업 시작.
0일차와 실제 귀환 결과는 아직 연결 전이다. 최신 구현 범위는 [구현 기능과 총괄 Manager 구성안](../../개발/FeatureManagerMap.md)에서 확인한다.

## 화면 설계 원칙

| 원칙 | 화면에서 지키는 방법 |
| --- | --- |
| 첫 루프에서 읽혀야 하는 것을 먼저 | 2D 초상·대사·알려진 위험·요리 효과 비교·귀환 원인은 첫 본영업 루프에서 읽을 수 있어야 한다. 상세 장식·추가 연출은 이후 보완한다. |
| 공식은 숨기고 결과는 보여 준다 | 무엇이 무엇을 막는지는 칩과 칸으로 보여 준다. |
| 고르기 전에 결과를 보여 준다 | 요리를 고르는 순간 완성될 효과를 미리 보여 준다. 위험은 수첩에 기록된 만큼만 보인다. |
| 결과는 원인과 함께 | “부상”만이 아니라 “열 2칸 모자랐다”로 보여 준다. |
| 색만으로 구분하지 않는다 | 여섯 위험 축의 색 규칙은 일관되게 쓰되 그림·글·아이콘을 함께 쓴다. 🔴 UI 색감·글꼴·아이콘·말투는 팀 논의 후 정한다. |

## 시간이 멈추는 화면

| 상태 | 손님 입장·이동·기다린 시간 | 6초 자동 조리 |
| --- | --- | --- |
| 쿼터뷰 일반 운영 | 진행 | 진행 |
| 대화·수첩·재료 선택 | 정지 | 진행 |
| 일시 정지 메뉴·아침 보고·회상 | 정지 | 정지 |

화면을 겹쳐 열었다가 하나만 닫아도 남은 화면의 정지 사유는 유지한다.
조리 잔여 4초에 대화 10초를 했다면 대화 중 완성되고, 화면을 닫으면 그 주문의 접시가 완성 상태로 기다린다.

## 조작 (3D 버전)

| 입력 | 동작 |
| --- | --- |
| W A S D | 이동 |
| E | 가까운 대상과 상호작용 (맞이하기, 자리 안내, 카운터 열기, 접시 들기·내기) |
| 마우스 | 대화·주방·보고·준비 화면 선택, 대사 속 단서 클릭 |
| Tab | 수첩 열기 |
| Esc | 일시 정지 메뉴: 이어하기·저장·불러오기·환경설정·끝내기 |

- Esc의 ‘이어하기’는 현재 세션을 재개하고, 최근 자동저장의 일차와 날짜·시각을 표시한다.
- 타이틀의 ‘이어하기’는 최신 유효 저장의 일차 시작으로 돌아간다. 저장 기준은 [제작 순서와 저장 기준](../09-승인과제작기준/02-제작순서와저장기준.md)을 따른다.
