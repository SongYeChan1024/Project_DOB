## 제작 순서

규칙 잠금 → 첫 안내 1명+병행 연습 2명과 다음 아침의 첫 플레이 → 하루 전환·보고·저장 → 임시 엔딩 → 5층·22레시피·단골 확장 → 외부 플레이·빌드 검증.<br>
→ 2026-11-24 현행 순서: 1일차 본영업 루프 → 데모 엔딩(실제 서빙 12명 이상인 날의 마감·정산 후) → 0일차 튜토리얼 → 남은 시간에 스토리. [구현 기능과 총괄 Manager 구성안](../../개발/FeatureManagerMap.md)

첫 검증은 1~2층, 최종 제공 목표는 5층이다.

개발 기간은 실제 제작 검증 후 재산정한다.

## 저장 기준

일일 정산이 끝나면 효과를 한 번만 적용하고 일차를 넘긴 뒤, 다음 날 시작 시점을 원자적으로 자동저장한다.<br>
수동 저장은 언제든 가능하며, 현재 일차의 시작 시점 스냅샷을 별도 수동 슬롯에 저장한다.<br>
쓰기 전에 “불러오면 1일차 시작 시점부터 다시 시작합니다. 저장하시겠습니까?”(1일차 예시)로 확인한다. 취소하면 아무것도 바뀌지 않고, 저장한 뒤에는 현재 플레이를 이어간다.<br>
불러오기는 그날의 진행을 버리고 저장된 일차의 시작부터 시작한다. 타이틀의 이어하기는 저장된 일차 시작 스냅샷을 불러오고, ESC의 이어하기는 현재 세션을 재개한다.

`Basement` 브랜치에서는 기존 `Title` 씬의 ‘새로 시작’으로 첫 손님 영업에 들어간다. ‘이어하기’는 최근 저장한 일차의 시작 상태를 복원하고, 영업 중 ESC 메뉴의 ‘끝내기’는 같은 타이틀로 돌아간다.

손님·방문·주문·보고·이야기 사실·처리 ID·난수 상태를 함께 보존한다.

## 튜토리얼 검토안

> 아래 「안내 1명+병행 연습 2명, 5~8분」은 0일차 연습안이며 본영업 루프 완성 후 제작한다([F14](../../개발/FeatureManagerMap.md#저장과-후속-제작--튜토리얼-사운드-스토리)). 1일차 이월 항목·최초 저장 시점은 🔴 미정이다.

안내 1명+병행 연습 2명, 총 3명이며 tutorial-spec 흐름을 아래 최신 수정과 함께 기준으로 쓴다.<br>
5~8분을 목표로 하고 첫날 3명에게는 개인 취약점을 넣지 않는다.

새 게임의 첫 손님부터 무작위로 등장한다. 해당 손님의 모습·목적지·대사가 첫 단서가 되며, 안내는 지금 접수한 주문에 맞춰 진행한다.

마늘 2개를 언제 쓸지는 플레이어가 정한다. 구운 빵+마늘을 쓰는 인간 마법사와 고기 구이를 쓰는 하플링 사제는 계산을 재현하는 시험 사례다.

단계 잠금·대사·드롭·체크포인트는 초안·시험값이며 구현 통과 결과가 아니다.<br>
T08·T10은 대화를 읽는 동안 조리가 완료될 수 있음을 안내한다.<br>
조리 잔여 4초에 응대 10초라면 응대 중 완성되고 닫으면 접시가 ready다.

## 결정 사항과 남은 검토

① 주 타깃 연령은 25~39세다.

② 주인공은 A안 카엘(인간, 20대 후반 남성), 조용한 야전 요리사다.<br>
옛 파티는 모라(드워프, 방패 전위)·시에(엘프, 정찰·경로)를 포함해 총 3명이다.

③ tutorial-spec 흐름에 대화 중 조리 진행·첫날 취약점 제외·카엘 기준 독백을 적용한다.

④ 대화·수첩·재료 선택 중에는 손님 입장·이동·기다린 시간을 멈추고, 6초 자동 조리는 계속 진행한다.<br>
일시 정지 메뉴·아침 보고·회상 중에는 조리도 멈춘다.

⑤ 개인 취약점을 판정에 추가한다. 손님 생성 시 30%(시험값), 체력을 제외한 한 축 +1이며 guestId에 고정한다.

⑥ 저장 경계·자리 변경·폐기·자기 처방·왕복 위험·장비·도시락의 세부 수치.
