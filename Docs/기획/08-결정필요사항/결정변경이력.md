[← 8장 목차](README.md) · [메인 기획서](../메인기획서.md)

## 예전 호감·입소문 수치안 원문 (2026-11-24 송예찬 결정, 팀 합의 전 시험값 · 이후 교체)

| 구분 | 규칙 |
| --- | --- |
| 대기 점수 | 2 − (기다린 초 ÷ 10, 내림). 기다린 시간은 입구에서 맞이를 기다린 시간과 착석부터 서빙까지 음식을 기다린 시간을 합한다. 대화·수첩·재료 선택 중에는 기다린 시간도 멈춘다. 예: 25초 → 0 *(점수 계산식과 25초 → 0 예는 지금도 같다. 대화·수첩·재료 선택 중 정지는 FeatureManagerMap F2의 「Esc만 정지」로 대체)* |
| 기다리다 떠남 | 대기 점수가 0 아래로 내려가는 순간(30초) 손님이 떠난다. 던전에 가지 않고 금화도 없다. 호감 −1, 그날 입소문 −1 |
| 맛 점수 | 맛 점수 − 2. 좋아하는 맛 하나당 +1(최대 +2), 싫어하는 맛 −2. 좋아하는 맛도 싫어하는 맛도 없으면 0 |
| 던전 결과 | 대성공 +2 · 성공 +1 · 간신히 0 · 부상 0 (🟡 간신히·부상 감점 여부) |
| 반영 시점 | 대기 점수 + 맛 점수 + 던전 결과를 다음 아침 귀환 보고에서 한 번에 반영하고 이유를 함께 보여 준다. 예: 「기다림 +2 · 입맛 +1 · 대성공 +2」. 떠남·돌려보냄의 −1은 그날 정산에서 반영한다. 호감은 0 아래로 내려가지 않는다 |
| 단골·사연 기준 | 한 방문에 최대 +6이 오르므로 기존 기준을 약 3배로 올린다. 호감 9 단골 전환, 9 · 21 · 36 사연 해금, 15 이상 재료 약속, 21 이상 대사 단서 두 개, 36 전리품 +1. 호감 범위 0~36 *(지금도 같다)* |
| 입소문 점수 | 어제 손님 중 (맛 점수 3 이상으로 끝난 식사 수 + 성공 이상 귀환 수 − 기다리다 떠난 손님 수). 아침 귀환 보고가 끝날 때 매일 새로 계산하고 누적하지 않는다 |
| 오늘 손님 수 | 기본 3명 + (입소문 점수 ÷ 2, 내림). 3명 아래로 내려가지 않는다. 준비 화면 「오늘의 소식」에서 늘어난 이유를 보여 준다. 🟡 상한은 플레이 테스트로 정한다 |
| 첫날 튜토리얼 | 손님 3명 고정. 기다린 시간과 떠남을 끈다(대기 점수 2 고정). 세 손님 모두 정답이면 입소문 3 → 둘째 날 손님 4명 |

## 그 밖의 예전 서술 원문

**호감 서술 (2026-11-23)** — 음식이 입에 맞으면 호감이 오르고, 평범하면 유지하며, 싫으면 내려간다. 좋아하거나 싫어하는 맛이 하나도 없으면 기본 맛 점수 2다. 던전에서 음식이 도움이 됐다면 다시 찾아올 동기가 생긴다. 재방문 응대에서는 이전 식사를 떠올리는 말로 취향을 암시한다.

**손님 반응 추가 기획안** — 손님별로 기다린 시간을 보고 호감도 차감을 판정한다. 식후에는 음식이 그 손님의 입맛에 맞았는지로 입소문과 호감도를 각각 판정한다. 다음 아침에는 같은 방문의 실제 탐험 결과로 입소문과 호감도를 다시 판정한다. 음식 맛을 좋아했어도 귀환 때는 다른 반응이 나올 수 있다. 같은 식후 반응이나 같은 귀환 보고를 다시 열면 기록된 결과를 표시한다. → 지금은 [4-8](../04-핵심플레이/08-호감과입소문.md)의 방문 점수 하나로 합쳤다. [손님 반응 흐름도](../04-핵심플레이/흐름도/04-손님반응.png)

**수첩 칸 (2026-11-24)** — 플레이어가 평문 대사에서 단서 표현을 찾아 클릭하면 그 말에 밑줄이 생기고 수첩에 손님별로 기록된다. 해당 위험 줄은 첫 발견 때 나타나며, 서로 다른 단서를 찾을 때마다 한 칸씩 찬다. 같은 표현을 다시 눌러도 칸 수는 유지된다.

**돌려보내기 대상 불일치 (🟡, 2026-11-24 해소)** — 돌려보내기 호감 −1의 대상이 메인 기획 4-1(단골만)과 4-8 호감 표(전 손님)에서 달랐다. 「모든 손님이 guestId별 호감을 누적」 결정에 맞춰 4-8 기준(전 손님)을 제안했고, 같은 날 전 손님 −4로 정리됐다.

**하루 전체 플로우 그림 (구글 메인기획서 그림 2)** — 구 버전 참고도다. 그림의 「5층 대성공 → 1막 완료」는 현재 조건이 아니다. 스토리 엔딩은 생존·위치 단서와 구조 준비·자기 처방을 검증한 뒤 출발하고 귀환 후 영업을 재개한다([4-10](../04-핵심플레이/10-후속스토리조건.md)).

**영업 시간 결정 당시의 입장 간격 질문 (🔴, 2026-11-24 일부 해소)** — 영업 시간이 없어졌으므로 손님이 입구에 나타나는 간격과 순서(빈자리가 생기면 다음 손님 입장 등)를 정해야 했다. 이슈 #30에서 간격은 무작위로 정했고, 최소·최대 간격·줄 인원·순서는 아직 남아 있다.
