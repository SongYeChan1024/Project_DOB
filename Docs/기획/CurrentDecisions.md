## 게임과 제작 범위

손님의 상태를 읽고 안전한 귀환을 위해 요리하는 식당 경영이다.
3D 쿼터뷰 운영 중 E로 손님을 맞이하고, 1인칭 응대 구도의 2D 초상·대사·아이콘으로 단서를 읽는다.
재료를 간단히 직접 투입하고 조미료를 선택한 뒤 확정하면 6초 자동 조리한다.
기본 재료인 밀가루·감자·고기는 무한·무료이며, 금화·양념이 없어도 영업을 계속한다.
게임 오버 분기는 추가하지 않는다.

아침 귀환 보고 → 준비 → 영업 → 마감 → 다음 아침으로 이어진다.
동시 좌석 수와 하루 총방문 수는 분리한다.
💡 시작 3석·총방문 6명·화구 2개·영업 약 180초는 시험값이다.
마감은 새 접수를 닫고 접수한 주문을 마무리한다.
고정 설치 소품과 연결 좌석의 효과를 기본으로 하며 자유 배치·거리·방향·복수 중첩은 확장 범위다.

첫 검증은 1~2층, 최종 제공 목표는 5층·레시피 22개다.
안내 1명+병행 연습 2명과 다음 아침 → 하루 전환·보고·저장 → 임시 엔딩 → 5층·단골 확장 → 외부 플레이·빌드 검증 순으로 진행한다.
개발 기간은 제작 검증 후 재산정하며 예전 README의 11일을 고정 일정으로 적용하지 않는다.

## 타깃·주인공·옛 파티

- 주 타깃은 25~39세, PC에서 대화·추리·가게 성장을 즐기는 이용자다.
- 보조 타깃은 같은 취향의 15~24세와 40세 이상이다. 표현은 유혈 대신 붕대·지친 표정으로 전달한다.
- 플레이 테스트는 25~34세와 35~39세를 함께 모집한다.
- 주인공은 A안 카엘(인간, 20대 후반 남성), 조용한 야전 요리사다.
- 디자인은 메인 노션 Character Image Reference 토글의 A안 남성 시트가 기준이다.
- 옛 파티는 주인공 포함 3명: 카엘, 모라(드워프·방패 전위), 시에(엘프·정찰·경로).

## 개인 취약점

플레이어는 손님의 모습에서 그 사람만의 약한 곳을 찾아 함께 대비한다.

| 항목 | 규칙 |
| --- | --- |
| 발생 | 생성 시 30%(시험값) 확률로 한 축 +1 |
| 대상 | 독·열·냉기·어둠·함정. 체력은 피곤함 컨디션이 맡으므로 제외 |
| 유지 | guestId에 고정. 재방문·단골 전환·불러오기 뒤에도 유지 |
| 기록 | 확인한 취약점은 수첩 단골 탭에 기록 |
| 계산 | 종족·컨디션과 함께 먼저 합산하고 직업 보정을 뒤에 적용. 종족 약점과 같은 축이면 합산 |
| 첫 소개 | 첫날 안내 3명에게는 제외. 둘째 날 처음 만나는 손님에게 그림과 대사로 한 번 설명 |
| 확률 데이터 | personalWeaknessChance: float, 0.3 |
| 손님 저장 | personalWeaknessAxis: 위험 축 enum 또는 없음 |

| 축 | 일러스트 레이어 |
| --- | --- |
| 독 | 기침·창백한 얼굴 |
| 열 | 화상 자국 |
| 냉기 | 떨림·목도리 |
| 어둠 | 찡그린 눈 |
| 함정 | 절뚝거림 |

축마다 1개, 총 5개 레이어다. 그림·대사·아이콘을 함께 쓰고 색만으로 구분하지 않는다.
예를 들어 수인과 기침 취약점이 겹치면 독 +2다.
요리·양념·화덕·자리 효과를 합산하고 돌발·활력 여유 보험을 처리한 뒤 최종 부족 합으로 등급을 정한다.
30%는 플레이 테스트 후 조정한다.

## 튜토리얼 수정

tutorial-spec 초안의 첫 인간 마법사(독·체력) → 두 손님 동시 응대 → 다음 아침 보고·양피지 독백 흐름을 기준으로 쓴다.
목표 길이는 5~8분이다.
첫 손님은 비피곤 1층 인간 마법사, 구운 빵+마늘로 독 1·체력 1을 대비한다.
시작 마늘 2개로 첫 안내와 셋째 연습을 해결하고 둘째 연습은 고기 구이를 사용한다.
응대·재료 선택·수첩의 자동 조리 표를 「진행」으로 바꾼다.
T08·T10은 읽는 동안에도 조리가 완성될 수 있다고 안내한다.
확인 기준은 「잔여 4초에 응대 10초 → 응대 중 완성, 닫으면 접시 ready」다.
첫 양피지 독백과 그림은 카엘(A안) 기준이다.
대성공 예: 「그릇이 비었다. 돌아올 힘까지 담겼던 모양이다.」
단계 잠금·대사·드롭·체크포인트는 초안·시험값이며 구현 통과를 뜻하지 않는다.

## 관계·스토리·엔딩

모든 손님이 guestId별 호감을 누적한다.
단골이 되어도 과객 때 이름을 유지하고 [단골] 태그만 추가한다.
단골 자격과 개인 사연 배정은 분리한다.
같은 종족·직업의 A/B/C 후보가 모두 사용되어도 단골이 되며, 공용 단골 반응을 사용한다.
💡 호감 3 전환, 3·7·12 사연 해금은 시험값이다.
60개 이름·42개 사연 조각·270장면 구성은 유지한다.

5층은 사건 장소이며 던전의 마지막 층이 아니다.
생존·위치·접근 경로·장비·자기 처방과 도시락 준비를 검증하고 계단 출발로 이어진다.
5층 대성공만으로 엔딩을 열지 않으며 실패나 희귀 재료 획득을 필수 진행 관문으로 강요하지 않는다.
귀환 후 AfterReturn으로 전환해 금화·재료·설비·단골·열린 층을 유지하고 영업을 재개한다.
보고별 짧은 독백과 주요 양피지 편린의 최초 해금을 분리하고, 재생·생략으로 보상이나 필수 사실을 중복 처리하지 않는다.

## 남은 검토와 문서 적용

⑥ 저장 경계·자리 변경·폐기·왕복 준비의 세부 기준은 검토 대기다.
저장 가안은 준비 완료·마감·귀환 결과 확정 자동 저장, 영업 중 종료 시 영업 시작 복귀다.
손님·방문·주문·보고·사실·처리 ID·난수 상태를 함께 보존한다.
자기 처방·왕복 위험·장비·도시락의 구체 검증값과 최종 대사는 작성이 필요하다.
