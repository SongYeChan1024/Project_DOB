## 지금의 제작 순서 (💡 2026-11-24 기준, 팀 합의 전)

| 순서 | 만들 것 | 완료 기준 |
| --- | --- | --- |
| 1 | 1일차 본영업 루프 | 손님 생성 → 응대·추리 → 착석 → 조리·서빙 → 식후 반응·퇴장 → 마감·당일 정산·자동저장 → 2일차 아침 귀환 보고·보상·입소문 정산 → 준비 → 다음 영업까지 이어진다. |
| 2 | 데모 엔딩 | 본영업 하루에 서로 다른 손님 12명 이상에게 실제 서빙을 마친 날, 모든 방문이 끝나고 마감 정산을 확인하면 엔딩으로 넘어간다. |
| 3 | 0일차 연습 영업 | 본영업 루프 완성 뒤 붙인다. 게임 안에서는 1일차보다 먼저 온다. |
| 4 | 스토리 | 데모 완성 후 남은 시간에 첫 양피지 독백·단골 사연·5층 구조 중 구현할 범위를 정한다. |

- 첫 루프의 필수 사운드 신호(입장·조리 완성·서빙·금화·귀환 도장)는 1번 루프와 함께 다룬다. 스토리는 사운드·데모 뒤에 온다.
- 첫 검증은 1층, 성장·밸런스 검증은 1~2층, 5층·레시피 22개는 확장 목표다.
- 🔴 개발 착수일과 기간은 실제 제작 검증 후 다시 산정한다.
- 기능별 구현 상태와 담당 Manager는 [구현 기능과 총괄 Manager 구성안](../../개발/FeatureManagerMap.md)이 기준이다.

## 설계 기준 비교

| 항목 | 현재 설계 기준 | 웹 프로토타입 |
| --- | --- | --- |
| 3D 씬 | 식당 중심 | 없음 (2D 카드) |
| 씬 흐름 | Title(플레이어 없음) → Loading → 게임 베이스. 게임 베이스가 카메라·플레이어·조작·게임플레이를 소유하고, 식당 레벨(스폰·좌석·주방)과 UI는 Additive로 불러온다. 프로토타입은 캡슐과 그레이박스를 쓴다. | 없음 |
| 전투·몬스터 AI | 직접 전투 없음 | 없음 |
| 손님 응대 | 실시간 운영: 대화·자리·자동 조리·서빙 | 한 명씩 차례로 |
| 자리 처방 | 소품 효과로 요리 보조 | 없음 |
| 조리 | 선택·확정 후 6초 자동 | 즉시 |

씬 구성의 현재 상태와 담당은 저장소 README 4장과 [씬 분리 설계](../../개발/SceneComposition.md)를 따른다. README 4장은 Dungeon(사냥) 씬 없이 일곱 씬 기준으로 정리되어 있다.

> **2026-11-23 당시 Unity 구현 기록** — Title → Loading → Restaurant(월드) + Gameplay(베이스) Additive 로드. Gameplay 씬에 GameplayCanvas가 함께 있어 UI 분리 전. 이후 Basement 브랜치에서 Basement + BasementRestaurant + BasementUI 구성으로 바뀌었다(FeatureManagerMap, main `14fd7e9` 기준). 최신 상태는 구성안에서 확인한다.

## 이전 개발 순서 제안 (이력)

10월 기준 제안 순서다. 현재는 위의 본영업 루프 우선 순서를 따른다.

| 단계 | 목표 |
| --- | --- |
| 기반 구성 | 5계층 폴더·asmdef·이벤트 버스 세팅, ScriptableObject 데이터 구조와 판정 엔진 이식. 프로토타입과 같은 입력에 같은 결과가 나오는지 테스트로 확인 |
| 식당 흐름 | 식당 그레이박스, 이동·상호작용, 손님 입장 → 안내 → 서빙 흐름 |
| 대화·추리 | 손님 외형·장비·컨디션 단서와 대화 데이터 연결. 임시 표시로 추리 흐름 검증 |
| 조리·보고 | 3D 재료 투입·자동 조리·서빙·귀환 흐름 연결. 임시 조작으로 검증 |
| 루프 통합 | 하루 루프 완성 (v0.1-alpha) |
| 플레이 검증 | 팀 플레이 테스트, 자리 처방과 실시간 영업 검증 (v0.2-test) |
| 성장 확장 | 최종 5층·22레시피·단골 사연·개량 확장. 첫 검증은 1~2층부터 |
| 후속 연출·마감 | 첫 루프 UI를 바탕으로 아트·사운드·장식 보완, 외부 플레이·밸런스·새 환경 빌드 검증 |
| 배포 준비 | 빌드 (v1.0) |

2026-10-30 승인 당시의 순서(규칙 잠금 → 첫 안내 1명 + 병행 2명 → 하루 전환·보고·저장 → 임시 엔딩 → 5층·단골 확장 → 외부 플레이)는 [제작 순서와 저장 기준](../09-승인과제작기준/02-제작순서와저장기준.md)에 보존한다.
