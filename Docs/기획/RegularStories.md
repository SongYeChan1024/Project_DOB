# 단골 사연 목록 명세

작성자: 송예찬 · 작성일: 2026.10.29

대사 원문은 「단골 사연 조각」(`RegularStoryFragments.md`)에 있다. 이 문서는 사연의 목록, 배정·해금 규칙, 데이터를 정한다.

## 0 기획 의도

손님 이름이 모두 무작위이므로 단골도 정해진 인물이 아니다. 그래도 단골마다 자기 이야기가 있어야 하고, 같은 종족·직업의 단골이 여럿이어도 이야기가 겹치면 안 된다. 사연을 뼈대와 조각으로 나눠 42개로 270장면을 만든다. 사연은 꼭 감동적일 필요가 없고, 뭉클한 이야기와 유쾌한 이야기를 섞는다(A 그리운 맛은 살짝 뭉클, B 갚을 것과 C 아래층 소문은 유쾌).

## 1 플레이어 규칙

단골과 친해질수록 그 손님의 이야기가 하나씩 열리고, 손님은 식당에 작은 물건을 남긴다.

## 2 시스템 규칙

### 사연 배정

1. 과객이 단골이 되면(`isRegular` = true) 그 손님의 종족·직업 조합에서 아직 배정되지 않은 후보(A·B·C) 하나를 무작위로 골라 `storyVariant`에 저장한다.
2. 배정은 저장 데이터 전체에서 조합별로 기록한다. 단골이 풀린 손님의 후보도 돌려주지 않는다.
3. 후보 3개를 모두 쓴 조합의 과객은 단골이 되지 않는다. 호감은 계속 쌓이지만 [단골] 태그와 사연은 없다.
4. 🔴 단골이 되는 조건(호감 몇에서 전환하는지)은 미정이다. 제안: 호감 3에 처음 닿을 때 단골이 되고 1단계 사연이 함께 열린다.

### 사연 해금

| 항목 | 규칙 |
| --- | --- |
| 해금 시점 | 다음 날 아침 귀환 보고에서 호감이 3 · 7 · 12에 처음 닿으면 그 단계가 열린다 |
| 여러 단계를 한 번에 넘음 | 순서대로 모두 열고, 보고에서 낮은 단계부터 차례로 보여 준다 |
| 호감이 다시 내려감 | 이미 연 사연과 받은 물건은 유지한다. 같은 단계는 다시 열리지 않는다 |
| 다시 읽기 | 수첩 단골 탭에서 열린 사연을 다시 읽는다 |
| 부상·휴식 중 | 손님이 오지 않는 동안에는 해금하지 않는다 |
| 대사 빈칸 | `{이름}`에 손님의 `displayName`을 넣는다. 연결은 `guestId`로 한다 |

### 장면 조립

| 단계 | 조립 |
| --- | --- |
| 1 (호감 3) | 뼈대 {후보}-1 앞줄 → 종족 조각 {종족}·{후보} 등장 → 뼈대 {후보}-1 뒷줄 |
| 2 (호감 7) | 뼈대 {후보}-2 앞줄 → 직업 조각 {직업}·{후보} 등장 → 뼈대 {후보}-2 뒷줄 |
| 3 (호감 12) | 뼈대 {후보}-3 앞줄 → 종족 조각 회수 → 직업 조각 회수 → 뼈대 {후보}-3 뒷줄 |

| 사연 후보 | `storyVariant` | int | -1 | 손님별. 단골 전환 때 0~2 배정, 저장·단골 해제 뒤에도 유지 |

| --- | --- |
| Define | 뼈대·조각·보상 데이터 구조, 종족·직업·후보 enum |

## 4 UI·피드백

- 귀환 보고: 호감 변화 아래에 "하루가 이야기를 들려줬다" 같은 한 줄과 사연 장면을 보여 준다.
- 수첩 단골 탭: 단골 이름 [단골] 태그, 연 단계(●●○), 다음 단계까지 남은 호감, 열린 사연 다시 읽기.
- 식당: 받은 물건을 진열 선반에 놓는다. 🔴 물건 9종의 외형과 진열 위치는 아트 작업 때 정한다.

### 구현 확인 기준

| 확인 상황 | 기대 결과 |
| --- | --- |
| 하플링 전사 두 명이 차례로 단골이 됨 | 서로 다른 후보를 받음 |
| 같은 조합의 네 번째 손님 | 단골이 되지 않고 사연도 없음 |
| 호감 2 → 5 | 1단계만 열림 |
| 호감이 7에서 4로 내려감 | 1·2단계와 물건 유지, 다시 7이 되어도 2단계가 또 열리지 않음 |
| 단골이 풀렸다가 다시 단골이 됨 | 같은 후보, 이어서 다음 단계 |
| 이름이 같은 다른 손님 | 사연·후보가 `guestId`별로 따로임 |
| 저장 후 불러오기 | 후보·단계·조합별 배정 기록이 그대로임 |
